## 阶段 4：后台任务轮询（2026-10-11）

基线：5d478a7。核对历史模块后发现它只共享了定时器，没有覆盖停止/重启和会话切换后的失效响应；本次保留阶段 2 的纯函数，新增公共调度器，依次接入训练、批量研判、报告 Store。

- 每个 Store 实例独立持有定时器和防重入锁；重复启动只创建一个定时器，慢请求期间不并行启动新的有效轮询。
- 停止或重启后旧轮询响应不能写状态、通知或解除新轮次的锁；重置或账号变化后，旧任务列表和旧报告文件响应失效。请求并未强制取消，返回时按轮次/会话检查是否仍可消费。
- 列表恢复和文件下载使用会话有效性检查；全部任务完成后自动停表仍允许当前账号的下载正常完成。
- 训练 DRAFT/FAILED、批量和报告 DONE/FAILED 的终态口径、每秒轮询、65/40/20 分钟等待上限、终态裁剪和已读规则保持不变。
- 批量结果回填与 completedTick、报告生成刷新计数、文件名和 Blob URL 清理、持久失败通知保持原状；训练的一次性通知集合改为按 Store 实例隔离。

## 阶段 5.3：会话恢复与查询等待（2026-10-11）

实施基线：a47b0cf。

- userStore 按实例共享在途 bootstrap；登录/退出优先于恢复，会话轮次和 AbortController 使旧恢复、旧登录、旧退出的成功/失败/finally 失效。重复退出复用在途请求，不自动重试写入接口。
- 恢复、认证、用户列表分别管理 loading，保留原聚合读取接口。用户列表只接受最新页与当前会话；无账号不发请求，旧失败不再显示到新会话。
- request 保留 Error/message 兼容性，新增 HTTP 状态码、传输错误码及未登录/超时/取消/网络/HTTP 分类；旧会话请求的 401 不清除新凭据或触发跳转。
- getMe 单独设置 10 秒等待上限，getUserList 设置 15 秒；全局 timeout 保持 0。登录、退出、上传、训练、批量任务、报告导出及 AI 流的等待策略不统一修改。
- 登录与退出 API 仅在当前认证操作仍有效时更新 CSRF；退出 POST 保留请求所需的原 CSRF，旧退出结束后不能清除新登录的 token。
- main 委托可独立验证的 startApplication，仍在会话恢复后安装路由和挂载应用。当前已登录会话 401 先清 Store，再跳到带原地址的登录页；错误密码的 401 仍由原表单处理。
- 未登录/401 保持普通登录页面；超时、断网或 5xx 通过已有错误提示区域说明重新登录或刷新重试。Login 的 template/style 不变，没有新增页面结构。
