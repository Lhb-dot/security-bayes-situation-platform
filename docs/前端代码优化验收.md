# 前端代码优化验收

实施范围：2026-10-10 规划的阶段 1～3。页面模板、样式、路由、业务操作和接口协议保持原状。

## 阶段 1：回归基线

- 复用历史 Vitest 配置、锁文件及说明文本、看板格式化、任务已读记录测试。
- 初始 3 个测试文件、35 条用例通过；`npm run build` 通过。
- 浏览器验证脚本已使用 history 深链导航，兼容旧 `#/path` 参数，检查实际目标路径，日志不再输出密码。可用 `--password-env` 传入验证密码。
- 浏览器依赖仅放在忽略目录 `tmp/qa-python`，没有改变后端依赖。

| 已有账号角色 | 直接访问的页面 | 初始结果 |
| --- | --- | --- |
| 超级管理员 | /overview | 总览和运行态指标可见 |
| 超级管理员 | 四个 /scenarios/:code/dashboard | 管理矩阵、建模覆盖、成员模块可见 |
| 网络场景管理员 | /scenarios/network_security/dashboard | 管理员首页可见 |
| 网络场景用户 | /scenarios/network_security/dashboard | 工作台可见，导航不出现用户管理和训练入口 |

以上 7 次浏览器检查通过，截图存放于忽略目录 `tmp/frontend-baseline`。当前数据库部分场景没有真实样本；这些结果证明页面加载、会话恢复和关键模块存在，不代表已验证真实训练或报告生成。

复用命令：`npm --prefix frontend run test`、`npm --prefix frontend run build`。
浏览器验证：`python scripts/verify_page_render.py --route /overview --present 平台运行总览 --password-env QA_PASSWORD`，需 Python 环境中可导入 websockets。

## 阶段 2：基础工具

- 统一 Unix 秒转换、北京时间字符串解析和 UTC/带时区 ISO 解析；训练、批量、报告任务和推理记录使用明确的来源解析函数。
- 保留推理记录的显示格式、无效值回退和任务计时回退；看板现有的本地时间格式化语义暂不调整。
- 三个 Store 共用当前账号读取、错误消息、终态判断、终态数量裁剪和过期清理；各任务的终态枚举、超时、轮询和通知仍独立。
- 5 个测试文件、50 条用例通过，覆盖时间来源、跨日、账号隔离、终态保留顺序和过期边界。
- 时间测试额外在 America/Los_Angeles 时区运行，10 条用例通过；`npm run build` 通过。
- 已核对推理记录的 template/style 与基线完全一致。
