# 前端代码优化规划

更新日期：2026-10-11。阶段 5 实施基线：524b391。本规划按用户明确的“只负责前端”重新划定实施与验收范围。

## 职责与边界

优化前端内部代码，保持现有页面视觉、布局、导航和正常业务操作。默认保留 Vue template/style，优先调整脚本、前端 API 封装与 Store；异常提示复用现有组件和样式。

实施范围为 frontend/ 中的业务代码、必要的前端测试与开发配置，以及相关说明文档。后端接口作为既定契约，前端可以补类型、适配返回值、取消自己的请求和限制等待时间，不改变接口协议。

不修改 backend/、数据库配置、Docker Compose、启动脚本或算法服务；不安装或启动后端运行依赖。不通过真实接口上传验收数据、训练/发布模型、创建推理记录、生成报告或清理数据库。后端故障只记录状态码、触发条件和脱敏后的现象，交由后端同伴处理。

浏览器检查使用独立会话及完整的模拟接口，覆盖 /api 请求，避免测试意外落到真实后端。只读联调是可选补充，不作为前端任务完成的前置条件。

## 当前核实的问题

- datasetStore 的列表、字段、预览和版本共用 loading、共享结果错用问题已在 5.1 修复。
- RiskInference 的场景 → 数据集 → 模型 → 字段 → 样本分页竞态已在 5.2 修复。
- userStore.bootstrap 尚无共享在途请求与会话版本保护；main.ts 等它结束后才挂载应用，而 request.ts 默认 timeout 为 0。会话查询长时间无响应时存在启动等待风险。
- ReportCenter 的详情已有 viewToken，但 loadReports 列表没有同等保护；列表刷新、翻页或多次调用时仍需防止旧结果回写。
- 两个 AI 接口各自实现 SSE 分块读取、解码和事件解析；reader 清理、跨块事件与错误/取消行为需要统一验证。
- 大页面仍包含大量脚本、模板和样式。先修复异步边界，再按业务抽取脚本，避免重构和缺陷修复混在一起。
- 模型中心列表已有 loadSeq；本轮保留并验证现有保护，按证据修补缺口，不机械重写全部请求。

## 前端验收方式

1. 先用模拟接口或可控 Promise 复现问题，再做最小修改；测试覆盖行为，不镜像实现。
2. 每项执行相关测试、类型检查和生产构建；修改影响全局请求/状态时运行全量测试。
3. 页面交互使用完整接口拦截及固定假数据，验证角色入口、快速切换、分页、失败重试、任务状态和下载。下载使用本地构造的 Blob，不创建服务端报告。
4. 同一角色、假数据和视口对比改动前后截图，核对页面模板与样式差异。
5. 检查 Git 差异范围，确保后端、数据库与团队共享运行配置没有变动。每个任务独立提交，按用户要求推送个人分支。

后端返回 500、数据库停机、算法执行失败或 PDF 渲染依赖缺失，均作为接口异常场景验证前端表现；不在本轮修复其服务端原因。
