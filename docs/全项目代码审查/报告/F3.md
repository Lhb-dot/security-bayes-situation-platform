### 2.1 修掉的 bug（4 处，均分区内、行为可论证不变）

### P1（**F6**：`frontend/src/api/riskEventApi.ts`）—— 风险事件 API 的线格式类型与真实响应不符

**证据链（三条独立证据，指向同一个根因）**

1. `riskEventApi.ts:23-28` 声明 `RiskEventPage.items: RiskEvent[]`，但 `riskEventApi.ts:44-49` 是
   `items: data.items ?? []` —— **没有做任何映射**，直接把后端原始行塞进「已映射形状」的类型里。
   `getRiskEventList`（`:11-20`）同理声明 `Promise<RiskEvent[]>`。
2. 后端返回的是**原始数据库行**：`backend/app/services/risk_view.py` 的 `view_of` 经

   `event_id: string`、`scenario_id: ScenarioId`（编码）、`status: '待处置'|'处理中'|'已处置'`（中文）。
3. 类型说谎的代价就是调用点被迫**双重断言**：
   - `AlertsView.vue:122`：`events.value = data.items as unknown as RiskEventItem[];`（**我的分区**）
   - `stores/riskEventStore.ts:41`：`this.events = (items as unknown as Array<Record<string, unknown>>).map(mapRiskEvent);`

   - `api/situationApi.ts:146,154`：同样先拿 `getRiskEventList` 再 `mapRiskEvent`

   而 `riskEventStore.ts:62` 必须先把中文转成枚举再 `as RiskEvent['status']` 断言回去
