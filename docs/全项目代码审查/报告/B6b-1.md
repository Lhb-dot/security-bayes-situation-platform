### C. 复杂度 / 可读性

1. **`config.py` 的超宽 `try`（改后 L20–38）**：一个 `try` 包住全部配置装配，只捕 `KeyError`。已随注释块删除从 70 行缩到 20 行；**未重构**（重构会把 `KeyError` 语义拆散，收益小于风险）。残留问题见 D-4。
2. **`main.py:create_app()` 连做 7 件事**（CORS + 2 个 router + 1 预热线程 + 5 个后台 runner + 1 个 mount）。可读性可接受（每个动作一行且各自有 docstring 函数），但**时序副作用**是真问题（D-6）。
3. **`common.py` 6 个 `validate_*`**：函数小、单一职责、有 docstring，**无问题**。
4. **`arff_reader.py` 三个读函数并存**（`read_arff` / `read_arff_header` / `tally_arff_column` / `count_arff_rows`）：看似重复，实为**性能分层**，docstring 已解释（`tally_arff_column` 注释：全量解析占首页耗时约 90%），且共享 `_parse_attribute` 保证口径一致。**保留，无问题**。
5. **`dataset_file_reader.read_dataset_file` 对同一文件两遍 IO**（`read_csv`/`read_arff` + `count_*`）。对预览接口可接受（ARFF 已另有 `tally_arff_column` 快路径）；**仅记录**。
6. **`pmwnb_demo` 删除后**：66 行、4 个函数，每个都有 docstring，复杂度已无问题。
