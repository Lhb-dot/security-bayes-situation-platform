## 2. 改动摘要

### 2.1 修掉的 bug（2 处，均为分区内、安全可修）

1. **SSE 流式请求在组件卸载时未中止（泄漏）**：`generateExplanation` 创建的 `explanationController` 原先只在「重新生成 / 停止生成 / 级联切换」三条路径被 `abort()`，**组件卸载这条路径没人管**——`onUnmounted`/`onBeforeUnmount` 在全文件零出现，`setInterval`/`setTimeout`/`addEventListener` 也零出现。离开页面后 SSE 连接会一直挂到服务端自然结束，回调继续往已卸载组件的 ref 追加正文。→ 新增 `onUnmounted` 中止。
2. **上一轮的 AI 评价会错配到下一轮结果上**：`handleInfer` / `applySample` / `runBatchJob` 丢弃上一轮结果时只清了 `inferResult`，**没有清 `explanationMarkdown` 也没有中止在途流**。复现路径：样本 #1 → 执行推理 → 生成 AI 评价 → 点样本 #2 → 执行推理 → **样本 #2 的结果卡下面显示的是样本 #1 的 AI 评价**（按钮文案还会是「重新生成」）。→ 三个入口统一调用 `resetExplanation()`。

### 2.2 消除的重复逻辑（分区内提取）

3. `resetInputState()`：三个级联 `watch` 里**逐字重复 3 次**的「清空输入区」块合并为一处。改前证据（`git show HEAD:…`）：
   - `watch(selectedScenario)`：7 行（`selectedDatasetId` + `selectedModelId` + 4 行输入区 + `resetResults`）
   - `watch(selectedDatasetId)`：6 行（`selectedModelId` + 4 行输入区 + `resetResults`）
   - `watch(selectedModelId)`：6 行（4 行输入区 + `samplePage` + `resetResults`）
   - 其中 `inputFields/inputData/samples/sampleTotal/resetResults` 这 **5 行在 3 处完全逐字相同**；`resetInputState()` 收下这 5 行，另两行（`samplePage`、`selectedDatasetId/selectedModelId`）因语义不同留在各自 watcher 里。
4. `resetExplanation()`：从 `resetResults()` 里拆出「丢弃 AI 评价」，使 `resetResults` / `generateExplanation` / 三个丢弃结果的入口共用同一份清理逻辑。改前 `generateExplanation` 开头是 5 行手写清理（`abort()` + `explanationMarkdown/Error/Fallback` 三清），其中前 4 行与 `resetResults` 尾部逐字相同，只有 `new AbortController()` 必须留在原处。
5. `ensureModelSelected()`：`handleInfer` / `handleBatch` / `handleUpload` 里逐字重复 3 次的「未选模型 → warning + return」合并为守卫函数。
6. `isNumericField(field)`：`'float' || 'int'` 判定原先在 `buildInputData`、`applySample`、模板 `v-if`、模板 `:step` 共 4 处重复，统一为一个判定函数。
7. `watch(selectedModelId)` 里手写的模型查找（`publishedModels.value.find(m => String(m.model_version_id) === String(modelId))`）改为复用已有的 `selectedModel` computed——同一份查找逻辑原本存在两份。
