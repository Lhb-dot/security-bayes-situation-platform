## 5. 路径穿越专项结论

**结论：本分区不存在路径穿越，也不存在任何文件写入。**

- `report_export.py` **全文件零文件系统调用**：`grep -nE "os\.path|open\(|shutil|tempfile|makedirs" report_export.py` → 命中 5 行，**全部是绘图辅助函数 `_svg_open`（第 297 行定义、343/396/466/511 行调用）的函数名**，没有一处真正的 `open()`/路径拼接；`import os` 仅用于 `os.getenv`。

- 文件名只用于 `Content-Disposition`：`safe_filename` 用 `_UNSAFE_FILENAME_CHARS = re.compile(r'[\\/:*?"<>|\x00-\x1f]')` 剥掉分隔符与引号、`strip(" .")`、截断 60 字符、空标题回退 `report_{id}`；`content_disposition` 再用 `quote(filename, safe="")` 做 RFC 5987 编码。即使标题含 `../../etc/passwd`，结果也只是响应头里的字面文本，无路径语义。

## 6. 正确性与健壮性问题（按严重度）

### F1【高·已修】测试进程会真的启动定时报告调度线程

`report_scheduler.start()` 原判定为 `if "pytest" in sys.modules: return`。`python -m unittest` 下 `pytest` 不在 `sys.modules` → 判定为假 → **线程真的起来连库扫到期报告**。而 `app/main.py` 模块级 `app = create_app()`，`tests/test_application_structure.py:7`、`test_report_export_async.py:526`、`test_report_generate_async.py:214`、`test_batch_inference_async.py:305`、`test_training_async.py:221` 都 `from app.main import app` → 触发 `start()`。其余四个执行器（`training_runner:182`、`batch_inference_runner:283`、`export_job_service:233`、`report_generate_runner:227`）用的都是 `running_under_test_runner()`，**只有这一个漏了**。
修法：改用 `running_under_test_runner()`（该工具认 `__main__.__spec__.name ∈ {unittest.__main__, pytest, pytest.__main__}`，并有 `test_*.py` 文件名兜底）；`import sys` 随之成为未用导入，已删（`grep -n "sys\." report_scheduler.py` → 0 命中）。

### F2【高·已修】`report_generate_runner._execute` 会话创建失败 → 任务永久 RUNNING

原 `db = SessionLocal()` 在 `try` 之外。数据库不可用/连接池耗尽时异常直接越过 `except`，`finally` 里的 `job.finished_at = time.time()` 也不会执行（`finally` 属于 `try` 语句，`try` 之前抛出的异常不会进入它）→ 任务永远停在 `RUNNING`、`finished_at=None`，而 `_purge_locked()` 只清终态任务 → **永久占用一个任务位且前端一直转圈**。
修法：`db = None` + 把 `SessionLocal()` 移入 `try`，`except/else/finally` 中全部加 `if db is not None` 保护。测试 patch 的是 `app.db.SessionLocal`（`test_report_generate_async.py:74/92/106/119`），函数内 `from app.db import SessionLocal` 在调用时解析补丁，语义不变。

### F3【高·已修】`_overview` 混用 naive/aware datetime → 500

原：`sorted(records, key=lambda x: x[0].executed_at or datetime(1970, 1, 1))`。库里 `executed_at` 是 aware（`DateTime(timezone=True)`），只要**有一条记录 `executed_at` 为空**，排序键就变成 naive `datetime(1970,1,1)`，Python 3 比较 naive/aware 直接抛 `TypeError: can't compare offset-naive and offset-aware datetimes`（已实测复现）。经 `@service_call` 变成 500"服务器内部错误"，整份报告生成失败。
修法：兜底值改为 aware 的 `_SORT_EPOCH = datetime(1970,1,1,tzinfo=timezone.utc)`，并把有值的一侧统一过 `to_beijing()`（对 naive 按 CST 解释、对 aware 转 CST，**单调保序**，排序结果与原来在所有 aware 输入下完全一致）。已用 4 条记录（1 条 `executed_at=None` + 3 条 aware）实测通过。

### F4【中·已修】`run_due_scheduled_reports` 提交后重新取行无 None 保护

抢占 `commit()` 之后、`self.db.get(Report, report_id)` 之前，报告或账号可能已被删除（`delete()` 只删报告行，不通知调度器）。原代码直接 `self._refresh(report, owner)` 会在 `None` 上取属性抛 `AttributeError`；`except` 分支里的 `report.next_run_at = ...` 同样会二次抛错，**异常逃出 for 循环**，本批剩余报告全部不处理。
修法：取行后判空 `continue`（记 warning），`except` 分支用局部 `stale` 判空后再写。行为等价（正常路径不变），异常路径由"崩整批"变为"跳过/重试单条"。

### F5【中·已修】章节标题跨模块重复且失配是静默的

见 3.2。修法：常量单点定义 + 双向引用。

### F6【中·已修】HTML `<title>` 转义不完整

原 `(title or "态势报告").replace("<","&lt;").replace(">","&gt;")` 漏了 `&`（`&` 会原样进入文档，非法 HTML，且与文件内其它转义点口径不一致）。修法：`_html.escape(title or "态势报告", quote=True)`。`{title}` 在模板中只出现于 `<title>`（`grep -n "{title}" report_export.py` → 1 处，第 96 行），浏览器渲染结果不变（`A & B` 原本也被宽松解析为 `A & B`），因此**用户可见文案不变**，只是输出变为合法 HTML。

### F7【中·已修】`_PdfRenderer.render` 把异常对象当返回值

原 `result = holder[0] if holder else RuntimeError("PDF 渲染线程未返回结果")`：把异常**实例**塞进 `result`，靠下一行 `isinstance(result, BaseException)` 兜住。虽然当前恰好能抛出来，但"表达式求值成异常对象"是易碎写法（一旦有人删掉 isinstance 检查就会 `return` 一个异常对象）。修法：显式 `if not holder: raise RuntimeError(...)`，`result = holder[0]` 后再判 `isinstance`。失败语义与消息完全不变（测试断言 `RuntimeError` 与消息文本，仍成立）。

### F8【中·已修】`_key_events` 对同一条事件调用两次 `level_of`

原：`{"HIGH":...}.get(risk_view.level_of(e, thresholds), risk_view.level_of(e, thresholds))` —— 命中映射时也要求值、未命中时再算一次。`level_of` 含阈值比较与字典查找，属热路径（每个事件一次），且可读性差。修法：`level = risk_view.level_of(...)` 计算一次，映射抽为模块常量 `RISK_LEVEL_LABELS/RISK_STATUS_LABELS`（同时避免每条事件重建两个 dict）。**输出逐字不变**（已核对 `处理中` 而非"处置中"，与原字典一致）。

### F9【中·未修·跨区】`export_job_service._execute` 有与 F2 完全相同的问题

`export_job_service.py:195` `db = SessionLocal()` 同样在 `try` 之外（`:196`），失败即任务永久 `RUNNING`。该文件不在 B2 写区，**未改**，见第 11 节 P1。

### F10【中·未修·性能】`report_nl.polish_with_llm` 单次生成最多阻塞 30 秒

`generate_report_narrative` 对 analysis/guidance **各调一次** `polish_with_llm`，每次 `timeout=LLM_TIMEOUT`（15s）。LLM 不可达时最坏 15s×2=30s 纯等待，而生成路径是 `report_generate_runner` 的**单线程串行队列**（`_loop` 一次一个任务）→ 一个报告卡住，后面全部排队。且 `create_job` 的 TTL 只清终态任务，RUNNING 任务不清理，堆积时前端表现为"长时间 pending"。
未改理由：属行为/性能取舍（是否保留 P2 润色、超时多少、是否合并成一次调用），改默认值会改变"报告是否被润色"这一可观察行为，超出"等价重写"范围。建议 Lead 决策：合并为单次调用（两段文本一次请求）或把 `LLM_TIMEOUT` 降到 3–5s，或按环境变量关闭润色。

### F11【低·未修】`report_scheduler.stop()` 不 join、不置空 `_thread`

`stop()` 只 `_stop.set()`；线程最坏要等一个 `_stop.wait(interval)` 周期（`DEFAULT_INTERVAL_SECONDS`）才退出，期间 `_thread` 仍指向旧线程。由于 `start()` 的幂等判断是 `if _thread is not None and _thread.is_alive(): return`，**stop 后立即 start 会因旧线程仍存活而静默不启动**（`_stop.clear()` 已被跳过）。实际影响低：生产只在进程退出时 `stop()`，测试因 F1 已不再起线程。
未改理由：改 `stop()` 语义（join 或置空 `_thread`）属于行为变更，且 `stop()` 无生产调用点（`grep -rn "report_scheduler import" backend/app` 仅 `main.py` 的 `start`），不确定是否有测试依赖"stop 后线程仍存活"的现状。建议 Lead 决定是否加 `join(timeout=...)`。

### F12【低·结论：不是缺陷】`_serialize` 的 `db.get(Scenario, ...)` 不是 N+1

`get_list/list_scheduled` 每行调一次 `self.db.get(Scenario, report.scenario_id)`。`Session.get()` **先查 identity map**，同一场景在整页内只发一次 SQL；库中 `scenarios` 仅 4 行，因此每页最多 4 次额外查询，不构成 N+1。**不做改动**（改成批量预取只会增加代码而无实际收益）。

### F13【低·未修】列表接口把正文全文当 `summary` 返回

`_serialize` 无条件 `"summary": report.content`（`report_service.py:108`），即使 `include_report_data=False`（列表模式）。一页 200 条 × 数千字正文 → 列表响应体积可达 MB 级；`summary` 语义上也应是摘要而非全文。
未改理由：改字段内容/长度会改变 API 响应体（前端可能用 `summary` 做列表预览），属对外契约，按协议只报告。

### F14【低·未修】`avg_risk_prob` 为 `None` 时正文显示 `0.000`

`_render_content:826` `f"- 风险样本平均概率：{(ov.get('avg_risk_prob') or 0):.3f}"`：无风险样本（`avg_risk_prob=None`）与真实均值 0.0 都渲染成 `0.000`，读者无法区分"无样本"与"概率为 0"。
未改理由：改文案即改用户可见输出（测试 `test_report_content.py` 对 `_render_content` 有断言）。建议 Lead 统一决定改成 `—`。

### F15【低·未修】`ReportCreate.file_path` 死字段 + `scheduled` 契约自相矛盾

- `file_path`：路由传入 → 落库 → 无人读（第 4 节）。
- `scheduled/interval_days`：`ReportCreate` 里可传，但 `create()` 对 `scheduled=True` **恒返回 400**（要求走 `/generate` 或 `update_schedule`），即 schema 允许、服务层拒绝。属接口设计遗留，见第 11 节 P2。

### F16【低·未修】`_feature_analysis` 用 `(attribute, value)` 作键，`(None, None)` 会合并

若某条解释数据缺 `attribute` 与 `value`，不同样本会被合并到同一个 `(None, None)` 桶并累加权重，可能挤进 Top10。已确认现有数据里 `attribute` 来自模型解释字典的键（不为 None），**未能证实可触发**，故只报告不修改（修改会改变 Top10 数值结果）。

### F17【低·未修】`report_nl.build_analysis_nl` 局部变量 `total` 遮蔽
