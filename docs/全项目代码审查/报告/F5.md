## 3. 改动摘要（每项一行）

**修的 bug（3 处，均为分区内、行为可判定的错误）**

1. `RiskEventDetailView.vue`：403 死分支 —— 旧代码比对 `'无权查看该事件' || '无权访问该场景'`，后端从不产生这两条文案（后端统一 `"无权限操作"`，见 §5-D1 证据），导致 `denied` 永远为 `false`，403 落到通用错误卡 + 一个必然失败的重试按钮；改为与 `DENIED_MESSAGE`/`NOT_FOUND_MESSAGE` 比对，模板里原本不可达的 `<p>无权查看该事件</p>` 分支恢复可达。
2. `InferenceRecords.vue`：组件卸载未中止 AI 评价流 —— `generateExplanation` 的 `fetch` 流在 `onBeforeUnmount` 时既没 `abort()` 也没停写，路由切走后仍持续写已卸载组件的 ref，并把流留在后台跑完；新增 `onBeforeUnmount` 中止 + 序号失效。
3. `InferenceRecords.vue`：过期响应竞态 —— 先发出的 `getInferenceExplain` 后回来时，会覆盖后打开记录的正文，并把新流程刚设上的 `explanationLoading` 提前清掉；`generateExplanation` 的 `finally` 还会把新流的 `explanationController` 置空，导致新流再也无法 `abort`。引入 `explanationRequestSeq` 序号，全部 await 之后与 `finally` 均按序号判定。

**删除的死代码（4 项，均附零引用证据，见 §4）**

4. `hiddenForUser`：`guards.ts` 声明 + `index.ts` 赋值，全仓无读取方 —— 两处一并删除。
5. `App.vue` 11 个 `isXxxPage` 计算属性 + `isNavActive()` + `handleNavClick()` 的 `router.push(item.path)` 回退分支 —— 导航项改为自带 `action`/`isActive`，这 13 个符号全部消失。
6. `Login.vue` 中第三份 `roleLanding` 副本（3 分支 `router.push`）—— 改为复用 `router/guards.ts` 的唯一实现。
7. `router/index.ts` 中第二份 `roleLanding` 副本（`/` 的 `redirect` 内联三元 + 角色判断）—— 改为 `redirect: () => { const user = ...; return user ? roleLanding(user) : '/scenarios'; }`。

**提取的具名常量（3 项，原为散落的魔法值/字面量）**

8. `App.vue`：`TASK_EXPIRY_SWEEP_MS = 60_000`（终态任务过期扫描间隔，原为裸 `60_000`）。
9. `App.vue`：`SCENARIO_NAME` 映射从 `myScenarioName` 函数体内提升到模块级（原每次求值都重建对象）。
10. `RiskEventDetailView.vue`：`FEATURE_PREVIEW_LIMIT = 50`（脚本 `slice(0, 50)` 与模板 `> 50` 两处同一个数字，此前靠人工保持一致）。

**组织性改动（2 项）**

11. `App.vue`：`import` 语句全部上移到 `const router = useRouter()` 之前（原 `useRouter()` 夹在 import 之间，违反 ESM 惯例）。
12. `App.vue`：徽章文案抽成 `unseenBadge` 计算属性（原模板内联三元 `unseenCount > 99 ? '99+' : unseenCount`），并顺带把数字显式 `String()` 化，与 `'99+'` 分支类型一致。

**明确没有改的（见 §9）**：`meta.title` 的启用/删除、`?redirect=` 的消费、场景名/角色名映射的跨文件合并、状态流转放行 `待处置→已处置`、`'null'` 特征值渲染、`guards.ts` 的 `to.path === '/'` 分支、`App.vue` 拆分、悬停面板的键盘可达性。
