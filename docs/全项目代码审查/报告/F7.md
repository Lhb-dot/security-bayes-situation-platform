## 3. 逐项审查结论

### A. 弃用（deprecated）

扫描命令（对 F7 全部 33 个文件）：

```powershell
$src = Get-ChildItem -Recurse -File frontend/src/components, frontend/src/views/Home/dashboard -Include *.vue,*.ts,*.css
Select-String -Path $src -Pattern 'beforeDestroy|filters:|slot-scope|\.sync|Vue\.set|\$listeners|v-on\.native|::v-deep|:global\(|@ts-ignore|@ts-expect-error|as any|: any|\bvar\b|console\.log|TODO|FIXME|XXX|type="text"'
```

**结果：全部 0 命中。** 逐项说明查了什么：

- **Vue 2 遗留**：`beforeDestroy` / `filters:` / `slot-scope` / `.sync` / `$listeners` / `Vue.set` / `v-on.native` → 0。本分区全部是 `<script setup lang="ts">` + `defineProps/defineEmits/withDefaults`，无 Options API 残留。
- **Element Plus 弃用**：`type="text"` 按钮 → 0（唯一用 EP 组件的是 `DataPreviewTable.vue` 的 `el-table`/`el-button`/`el-pagination`，`el-button` 用的是 `size="small" plain`）。`::v-deep`/`:deep()` → 0：本分区要覆盖 EP 内部类的两个文件（`DataPreviewTable.vue`、`dash.css`）用的是**非 scoped 全局 `<style>`**，因此不需要深度选择器（代价见 §8-3）。
- **Vue Router 旧 API**：本分区无路由定义（路由在 F5 分区），`DashboardHomeView.vue:18` 用的是 `useRoute()` 组合式 API ✓。
- **TS 语言层**：`any` → 0（含 `as any` / `: any`）；`@ts-ignore` / `@ts-expect-error` → 0；JS `var` 声明 → 0。
  （更正记录：`\bvar\b` 单独扫描有 **2 处命中**，逐条核对后确认都是 **CSS 自定义属性引用** `font-family: var(--font-ui)`，位于 `ScenarioCard.vue:121` 与 `dash.css:7`，**不是** JS 的 `var` 关键字 —— 用 `\bvar\b` 会把 `var(` 一起匹配进来，故该模式不能单独作为「无 var 关键字」的证据。）
  **非空断言 `!`**：改前 `DashTable.vue` 模板有 **2 处**（HEAD `:110` `asTag(...)!.tone` / `:111` `asTag(...)!.text`），**已全部消除**，`Select-String '\)!'` 现 0 命中 → **全分区现无 `!` 断言**。
- **项目层**：本分区不含 `legacy_model_routes.py`、`pmwnb_demo.py` 之类的旧路径。唯一「被新实现取代但残留在代码里」的就是 `DataPreviewTable.vue` 的 EP 旧版冻结列样式（EP 2.x 已改为 `.el-table-fixed-column--left`，见 §4-D2），**已删**。

**结论：A 类零遗留。**

### B. 残留 / 死代码

**B2. 未删 · 需 Lead 裁决：`dash.css:361-362` 的 `.d-tag--high` / `.d-tag--medium` 无产出点**

证据：

```powershell
Select-String -Path $src -Pattern "tone:\s*'(high|medium)'"
# 只命中 views/Model/ReportCenter.vue:338,340 (high) 与 :341 (medium)
```

但 `ReportCenter.vue` 的 tone 走的是**另一套类名**：

```ts
// ReportCenter.vue:765
:class="m.tone ? 'stat-card--' + m.tone : ''"
```

即 `stat-card--high` / `stat-card--medium`，与 `.d-tag--*` 无关。而 `.d-tag--*` 的唯一动态构造点是 `DashTable.vue:94`：

```ts
? { isTag: true, text: tag.text, cls: `d-tag d-tag--${tag.tone}` }
```

`DashTone`（`DashTable.vue:19-30`）的 11 个成员中，实际被调用的只有 `up`（4 处）、`down`（1 处）、`warn`（4 处）、`muted`（2 处 + `asTag` 默认值）、`ok`（8 处，Profile 页判定列）；`pending`/`processing`/`resolved`/`low` 由 `dashFormat.tagClass()`（`:52-56`）以**完整类名字面量**产出（`DashEvents.vue:26`）。**`high` 与 `medium` 无任何产出点** —— `tagClass()` 特意把 `HIGH` 映射到 `d-tag--pending`、`MEDIUM` 映射到 `d-tag--processing`。

**不删的理由**：`DashTone` 是 `DashTable.vue` **导出的公开联合类型**，`'high' | 'medium'` 是它声明支持的取值；`dash.css` 的这两条规则是在实现该类型的完整契约。删掉 CSS 会让两个「类型上合法」的 tone 渲染成无样式裸文本 —— 从「多余 2 条 CSS」变成「埋一个雷」。正确清理必须**同时收窄 `DashTone`**，那是接口变更 → 走提案 §7-4。（补充核查：该导出目前**没有任何外部按名引用**，只通过 `DashCell` 的成员类型传递 —— 详见 §8-22；这不改变上述结论，但说明「公开契约」眼下只是模块级声明。）

**B3. 未删 · 判定为防御性回退：`RiskLevelTag.vue:29` 的 `levelLabel[level] ?? level`**

`tsconfig.app.json` **未开** `noUncheckedIndexedAccess`（已核 `tsconfig.app.json` / `tsconfig.json` / `tsconfig.node.json` 及 `@vue/tsconfig` 继承链），且 `level` 是闭合联合 `'critical'|'high'|'medium'|'low'`、`levelLabel` 四个键齐全 → **类型上 `?? level` 是死分支**。但 `level` 的实参来自后端 `risk_level`（`ScenarioCard.vue:60` 传 `scenario.risk_level`，`RiskEventDetailView.vue:180` 传映射后的 `tagLevel`），越出契约时 `??` 能避免页面渲染出 `undefined`。**保留**（协议 §2「不确定就不要删」；项目通篇是「类型闭合 + 运行时兜底」的写法）。

**B4. 未删 · 重复定义 + 防御性回退：`ScenarioCard.vue:24-28` 的 `scenarioNameMap`**

### D. 正确性隐患

**D1. 空值被吞成 0（已修 3 处；这是简报里的「提案 A」）**

根因在 `dashFormat.ts:7-18`（`fmtInt` 7-11、`fmtNum` 14-18）：

```ts
export const fmtInt = (value: unknown): string => {
  const num = Number(value);
  if (!Number.isFinite(num)) return '—';
  return Math.round(num).toLocaleString('zh-CN');
};
```

`Number(null) === 0`、`Number('') === 0` 都是**有限数**，因此 `null` / `''` 被渲染成 `0`（`fmtNum` 同理渲染 `0.00`）；只有 `undefined` / `NaN` / `Infinity` 才落到「—」。

**受影响调用点（全部在 `DashKpis` 的非 raw 分支）**：

| 调用点 | 代码 | 修复前显示 | 应为 |
|---|---|---|---|
| `ProfileFlightdeck.vue:375` | `value: item ? item.pending : null` | 0 | — |
| `ProfileFlightdeck.vue:390` | `value: runtime.value ? trendTotal.value : null` | 0 | — |
| `ProfileGeological.vue:343` | `{ label: '待处置积压', value: item ? item.pending : null, … }` | 0 | — |
| `ProfileNetwork.vue:370` | 同上 | 0 | — |
| `ProfilePower.vue:343` | 同上 | 0 | — |
| `ProfilePower.vue:358` | `value: item ? activityTotal.value : null` | 0 | — |

**契约证据（调用方用 `null` 表达的就是「无数据」，不是「0」）**：`ProfileFlightdeck.vue:382` 的注释逐字写着「分母为 0 时不下结论，交给 DashKpis 渲染「—」」——这是**写下来的契约**，而修复前它并未兑现。

**修复**（`DashKpis.vue:22-35`，新增 `valueText()`）：

```ts
const valueText = (item: KpiItem): string => {
  if (item.raw) return String(item.value ?? '—');
  if (item.value === null || item.value === undefined || item.value === '') return '—';

};
```

'—' : fmtNum(mean)`）、`ProfilePower.vue:159-164`（`:160` 判空 + `:163` `raw: true`，靠 `value ?? '—'` 生效）、`ProfilePower.vue:210`、`WorkspaceFlightdeck.vue:51`、`ProfileFlightdeck.vue:383`、`ProfileGeological.vue:346`、`ProfileNetwork.vue:373`、`ProfilePower.vue:351`（`item && item.total ? fmtPercent(...) : null`）。**约定就是「调用点判空」**。在共享 formatter 里加 `=== null → '—'` 会一次性改变 20+ 个调用点的行为，属协议 §2 的「改大」，且无法在隔离环境内验证全部 20+ 处。**因此只在调用点补齐漏网的 3 处**（`DashKpis` / `DashEvents` / `DashScatter`）。

### 7-3【可选】`DashLine` / `DashColumns` 的 ResizeObserver 样板提取

**方案**：新建 `frontend/src/components/dashboard/useHostWidth.ts`：

```ts
import { computed, onBeforeUnmount, onMounted, ref } from 'vue';
export const useHostWidth = (fallback: number) => {
  const hostRef = ref<HTMLElement | null>(null);
  const hostWidth = ref(0);
  let observer: ResizeObserver | null = null;
  onMounted(() => {
    const host = hostRef.value;
    if (!host) return;
    hostWidth.value = Math.round(host.getBoundingClientRect().width);
    observer = new ResizeObserver((entries) => {
      const width = entries[0]?.contentRect.width ?? 0;
      if (width > 0) hostWidth.value = Math.round(width);
    });
    observer.observe(host);
  });
  onBeforeUnmount(() => { observer?.disconnect(); observer = null; });
  return { hostRef, viewWidth: computed(() => (hostWidth.value > 0 ? hostWidth.value : fallback)) };
};
```
