## 2. 改动摘要

### 2.1 修掉的 bug（2 处，均在分区内、可安全修）

1. **`ModelCenter.vue`：对比面板把模型列表整块吃掉，3~5 个模型永远选不到。**
   原模板是 `v-if="loading && !models.length"` → `v-else-if="error"` → `v-else-if="!models.length"` → `v-else-if="compareList.length >= 2"`（对比面板）→ `v-else`（模型列表）。
   勾满 2 个模型后命中对比面板分支，**模型列表连同卡片上的勾选框一起从 DOM 消失**，用户再也点不到第 3 个，
   于是 `compareIds.length >= 5` 的上限判断和「最多选择 5 个模型进行对比」提示成为**不可达代码**。
   证据：`frontend/README.md:51` 明确写「选择 **2-5 个**模型，按 Accuracy/Recall/Precision/Specificity/F1/G-mean 逐项对比并高亮最优」，
   说明设计意图是 2~5 个；且 `.compare-panel { margin-bottom: 18px }`（1252-1255 行）本就是给「面板在上、列表在下」的并存布局预留的间距。
   修法：把「对比面板 + 模型列表」一起包进 `<template v-else>`，面板内部仍用 `v-if="compareList.length >= 2"` 控制自身显隐。
   为控制 diff，块内子节点未重新缩进（只加了一对 `<template>` 标签 + 注释），语义与缩进无关。
2. **`Settings.vue`：`currentUser` 是快照 ref，切换账号后残留旧数据。**
   原来是 `const currentUser = ref<UserAccount | null>(null)`，只在 `onMounted` 里赋值一次。
   该组件是**常驻布局内的路由视图**，同一会话内切换账号（`userStore.logout()` → 换号登录）后若组件实例未重建，
   `isAdmin` / `canConfigureThresholds` / `accountRoleLabel` 等全部按旧账号渲染，会出现「已降权账号仍看到管理员阈值配置」的越权观感。
   修法：改为 `const currentUser = computed<UserAccount | null>(() => userStore.currentUser)`，并删掉 `onMounted` 里的赋值。
   安全性：`frontend/src/main.ts` 在 `app.mount('#app')` 之前 `await userStore.bootstrap()`，所以首个渲染周期 store 已有值，不存在「首帧为空」的回归。

- `ScenarioCenter.vue` 的 `@media (max-width: 1200px)` / `768px`：标准响应式断点。

**C.5 重复遍历 / N+1 / 可用内建替代**

- `ModelCenter.vue` `loadModels` 138-140：对 `data.items` 一次遍历同步对比缓存，O(n) 且不可避免。
- `ModelCenter.vue` `onMounted` 543-549：`allScenarios.value.map(getDatasets)` 是**按场景并发取数据集**（`Promise.all`），
  属后端无批量接口时的合理折中（4 个场景 → 4 个请求，非 N+1 放大）。**未改**，但记入 §8.2 存疑（可提案加 `GET /datasets?scenario_ids=`）。
- `allDatasets` 构造里对每个 dataset 做 `allScenarios.find(...)` → **O(n·m)**，4×19 规模无感；
  但可用一次 `Map` 预建索引替代。因收益微小、且改动会扩大 diff，**未改**，仅记录（协议 §3.C 要求指出）。

**C 结论：超长文件 2 个（拆分方案已给出，因 §1.7 禁止新建文件而未执行）；无超长函数；无 >3 层嵌套；
魔法值已提取 6 项、其余经论证保留；无 N+1；1 处 O(n·m) 查找已指出。**
