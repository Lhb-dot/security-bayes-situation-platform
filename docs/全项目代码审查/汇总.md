## 二、隔离机制（为什么 25 个代理能同时改一个仓库而不互相破坏）

`docs/全项目代码审查/审查协议.md` 的八条硬约束：

1. 写作用域 = **本分区文件 + 本分区报告文件**，别的一律不碰；
2. 分区两两不相交；
3. **共享面只提案**：需要改别人文件时，在报告里给完整 diff，**绝不落地**；
4. 禁止命令：`npm run build`、`vite build`、起停任何服务、`pytest`、写 `frontend/dist`、写 DB、写 `backend/lib/*.jar`、`git commit/checkout/stash/reset/clean`；
5. 允许的自验：前端 `npx vue-tsc --noEmit -p tsconfig.app.json --tsBuildInfoFile node_modules/.tmp/tsb-<分区>.json`（**私有 tsbuildinfo 是强制的**，否则并发互踩），后端 `python -m py_compile <files>`；
6. 并发错误噪声规则：只看自己分区内的错误；
7. **禁止跨文件改公开接口**，除非所有调用点都在同一写作用域内；
8. 除报告外不新建文件/目录。

**为什么不用 `git worktree`**：worktree 里没有 `frontend/node_modules`，`vue-tsc` 跑不起来 —— 故采用「主工作区 + 文件级互斥所有权」。

**踩过的坑（已写进协议与核验记录）**：
- `tsconfig.app.json` 固定了共享的 `tsBuildInfoFile` ⇒ 并发 `vue-tsc` 会互踩，必须 `--tsBuildInfoFile` 覆盖；
- 分区过大（>4,000 行 / >30 文件）会导致子代理**静默死亡**（无收尾消息、常常零改动）。实测安全规模：1,600–3,500 行 / 12–33 文件；
- `subagent` 并发上限 **8**；
- **`python -m py_compile` 抓不到 `NameError`** —— 已实证两次，故立 `tmp/import_sweep.py` 为强制门（见 §四）。
