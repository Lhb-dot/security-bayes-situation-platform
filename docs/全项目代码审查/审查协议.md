## 0. 目标

对整个项目（前端 + 后端 + 测试 + 脚本 + 迁移 + Java 算法服务 + 文档）做**深度代码审查 + 重构**，消除三类问题：

1. **弃用（deprecated）**：已废弃的框架/语言用法、被新实现取代但仍留在代码里的旧路径。
2. **残留（dead / leftover）**：死代码、死分支、未使用的导入/变量/类型/路由/常量、注释掉的代码、入库的构建产物、与代码不符的文档。
3. **复杂（over-complex）**：重复逻辑、超长函数、深层嵌套、魔法值、可内建替代的手写实现、N+1 查询。

**核心要求「对每个函数都去理解」**：不允许只做表面 grep 扫描。必须读懂每个函数在算什么、参数/数据从哪来、被谁调用、边界条件是什么。报告的「函数清单」一节就是这项要求的交付证据。

## 2. 重构原则

- **行为不变优先**：默认只改「怎么算 / 怎么组织代码」，不改「对外表现」。用户可见文案、字段名、数值结果、接口返回结构、路由地址不得变化。
- **删要删干净，也要删得有证据**：每个删除项必须有**零引用证据**（贴出 grep 命令与输出）。
- **不确定就不要删**：有疑问的写进报告，由 Lead 裁决。宁可少删，不可错删。
- **不引入新依赖**；**不改依赖版本**。
- **改小不改大**：不要把一个文件整篇重写。diff 规模要能被 review。
- 尊重现有风格：中文注释、现有命名习惯、现有目录约定。

## 3. 审查清单（逐项过，每项都要给结论，不允许只写「无问题」）

### A. 弃用（deprecated）

- **框架层**：Vue 2 遗留（`beforeDestroy`、`filters`、`slot-scope`、`.sync`、`$listeners`、`Vue.set`、`v-on.native`）；Element Plus 废弃 prop/事件、`type="text"` 按钮、`::v-deep`；Vue Router 旧 API。
- **语言层**：
  - Python：`datetime.utcnow()`、`distutils`、`imp`、`pkg_resources`、无 running loop 的 `asyncio.get_event_loop()`、`typing.List/Dict/Optional` 旧式注解（若项目已统一 `list/dict/X | None`）、`from typing import` 中已无必要的导入。
  - TypeScript：`any`、`@ts-ignore`、`@ts-expect-error`、掩盖真实 `null` 的非空断言 `!`、`var`。
- **项目层**：被新实现取代但未清理的旧路径。已知嫌疑：`backend/app/api/legacy_model_routes.py`、`backend/app/services/constants.py` 的 `ALGORITHM_STATUS_DEPRECATED` 相关死分支、`backend/app/algorithms/pmwnb_demo.py`、`backend/app/services/model_sim.py`、前端已被后端 `modeling` 字段取代的 `getModelVersionList` 回退、`backend/deprecated/**` 整块。

### B. 残留 / 死代码

- **未被引用的**：模块、函数、类、常量、变量、导入、类型、CSS 类、路由、API 封装函数、store action/state、DB 模型字段、测试用例。
- **死分支**：条件恒真/恒假的分支。**必须有证据**：类型定义 + 上游实际返回值 + 调用点。不许凭直觉断言。
- 注释掉的代码块、`console.log`、调试 `print`、`TODO`/`FIXME`/`XXX`、空 `<style>`、空函数、`pass` 占位、`return None  # noqa`。
- **重复定义**：同一类型/常量在多处声明；同一工具函数多份实现。
- **构建产物 / 缓存入库**：`__pycache__`、`*.pyc`、`*.class`、`dist`、`*.log`、临时脚本。**先用 `git ls-files` 确认是否真的被跟踪**——未跟踪的只是磁盘垃圾，不要写进「已提交死代码」。
- **过期文档**：与代码不符、指向已删除文件、提到的字段/接口/路由不存在。

### C. 复杂度（over-complex）

- 重复逻辑：同一段计算/格式化/校验在多处复制 → 提取。**仅当提取后的新位置也在你的写作用域内**，否则提案。
- 超长函数（> 80 行）、超长文件（> 800 行）：指出可拆分点与拆分方案。
- 深层嵌套（> 3 层）、复杂三元链、超长布尔表达式 → 具名化或提前返回。
- 魔法数字/字符串（阈值、状态码、单位、颜色语义、场景 key）→ 具名常量。
- N+1 查询、循环内 IO/查询、对同一集合的重复遍历 → 指出并给优化方案。
- 手写查找/排序/去重可用内建替代；可提前返回的重复条件判断。

### D. 正确性隐患（发现即报告；**能安全修的才修**）

- **空值与边界**：分母为 0、空数组/空集合、`None`/`undefined` 访问、越界索引、`int(None)`。
- **异常处理**：吞异常（`except: pass`）、过宽 `except Exception`、统一兜底装饰器掩盖真实错误（如 `@service_call` 把 `TypeError` 也变成 500）。
- **并发与状态**：全局可变状态、缓存无失效/无锁、`watch`/定时器/订阅泄漏、未清理的副作用。
- **安全**：SQL 拼接、路径穿越、权限校验缺失（越权读他人数据）、明文密钥。**不要打印密钥内容**。
- **一致性**：同一口径在多处实现不一致；文档与实现不符。

### E. 硬约束（越界即失败）

- **不改 Alembic 已应用的迁移内容**：历史不可变。只审阅并报告问题（如缺索引、字段类型不当、`downgrade` 不可用），新增迁移也走提案。
- **不改测试的断言语义**：可清理重复/死测试、可提升可读性，但**不得放宽或删除有效断言**。
- **不改 Java 算法源码的算法逻辑**：那是 vendored Weka 实现，改了会让已构建的 jar 与实验结果不一致。只做结构审查（谁引用谁、重复源码、死兼容类）并报告。
- 见 §1.6 与 §2。
