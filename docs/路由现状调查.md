- **404 兜底**：新增 `/:pathMatch(.*)*` → `views/NotFoundView.vue`；`App.vue` 的内容区渲染

## 一、`#` 从哪来

`frontend/src/router/index.ts:119`：

```ts
history: createWebHashHistory(),
```

hash 模式从项目初始就在（`git log -S "createWebHistory"` 无结果，从未用过 history 模式），所以地址恒为 `ai-security.readup.asia/#/reports`。

**为什么当初只能选 hash —— 因为有两条出口，只有一条能兜住深链：**

| 出口 | 配置 | 深链 `/reports` |
|---|---|---|
| nginx（主入口） | `vhost_aisec_ssl.conf:54-56` 有 `try_files $uri $uri/ /index.html` | ✅ 回 index.html |
| FastAPI 直连 `:12312` | `backend/app/main.py:101` `StaticFiles(..., html=True)`，**无 SPA 回退** | ❌ 404 |

FastAPI 这一条已实测（starlette `TestClient` + `StaticFiles(html=True)`）：

```
/                        -> 200 'SPA'
/a.txt                   -> 200 'file'
/reports                 -> 404 'Not Found'
/reports/                -> 404 'Not Found'
/scenarios/x/dashboard   -> 404 'Not Found'
```

**换 history 模式的前置条件**：在 `main.py` 的 `StaticFiles` 之前加一层 catch-all（未命中静态文件且路径无扩展名时返回 `index.html`），否则直连端口的入口全部 404。nginx 侧无需改动。

## 二、真问题

### 1. 无 404 兜底（高）

`routes` 数组里没有 `/:pathMatch(.*)*`。hash 模式下访问不存在的地址（如 `#/xyz`）→ 无路由匹配 → `App.vue` 中 `isLoginPage`/`isRiskPage`/`isNewRoutePage` 全为 `false` → **顶部栏在、内容区完全空白**，不提示也不跳转。

### 2. `/risk` 的权限注释与代码不符（中）

- `index.ts:37-38` 注释：「管理级角色（最外层 + 场景管理员）可训练」
- `index.ts:38` 实际 meta：`{ title: 'AI模型训练预测' }` —— **没有** `requiresAdmin`
- `guards.ts:50` 只拦带 `requiresAdmin` 的路由，全表仅 `/overview` 带（`index.ts:46`）

结果：导航里 `/risk` 对场景用户隐藏（`App.vue:175`），但**手敲 `#/risk` 能直接进训练页**。前端守卫不拦。

### 3. 权限有三份来源，彼此不知道对方存在

| 位置 | 机制 | 覆盖范围 |
|---|---|---|
| `index.ts` route meta | `requiresAdmin` | 仅 `/overview` |
| `guards.ts:50` | 读 meta 拦 SUPER_ADMIN 以外 | 同上 |
| `App.vue:169-182` | `navItems[].roles` 过滤导航 | `/overview` `/risk` `/users` |

导航隐藏 ≠ 路由可进。三者应合并为单一来源（建议：meta 里声明角色，导航与守卫都从 meta 推导）。

## 三、冗余与死数据

1. **`hiddenForUser` 全仓无人读取** —— `guards.ts:19` 声明、`index.ts:46` 设置，grep 无第二处引用。
2. **`meta.title` 全表 14 条都写了，零消费** —— 无 `meta.title` 读取、无 `document.title` 赋值；`index.html` 标题静态，`App.vue:128` 注释亦明说「不随路由变化」。
3. **路由 `name` 从未用于跳转** —— 全仓无 `push({ name: ... })`，导航一律 `push('/path')`。且中英混排：`'登录'`/`'场景中心'`/`'用户管理'` 与 `'ModelCenter'`/`'RiskInference'`/`'Settings'`/`'ReportCenter'` 并存。
4. **根路径落地逻辑写了两份** —— `index.ts:15-22` 函数式 `redirect` 与 `guards.ts:54-56` 的 `to.path === '/'` 分支（guards 自注「双保险」）；两者又与 `guards.ts:28-33` 的 `roleLanding()` 是三处同构的 if/else。
5. **命名与标签不一致** —— `/alerts` 的 meta.title 是「风险事件列表」，导航 label 是「告警中心」（`App.vue:174`）。
6. **标签逻辑写在 template 里**（`App.vue:241`）：
   ```
   item.path === '/settings' ? (isSuperAdmin ? '系统设置' : '设置')
     : (item.path === '/scenarios' ? (isSuperAdmin ? '场景中心' : '首页') : item.label)
   ```
   应下沉到 `navItems` 的数据构造里。

### 死代码

- `App.vue:144` `isSituationPage` 判 `/situation`，router 中**无**该路由
- `App.vue:204` `case '/situation'` 同上
- `App.vue:148-153` `isNewRoutePage` 的白名单里也含 `/situation`
