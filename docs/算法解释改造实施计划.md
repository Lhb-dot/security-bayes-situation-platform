## 分阶段路线

1. 统一算法输出：Java 预测服务保留既有预测字段，并增加只读 `feature_attribution`；Python 组装公共解释契约和算法专属明细，缺失项使用 `available=false`。
2. 场景配置：先完整配置网络安全字段字典、风险类型、推荐措施和人工复核建议，再用确定性的字段族目录补齐其他场景。
3. AI 接口：新增 `/api/v1/inference/explanation/stream`，使用每个用户自己的 OpenAI 兼容地址、模型和密钥；密钥服务端加密存储，接口只返回掩码。
4. 前端展示：在风险研判结果旁读取 SSE，拼接 Markdown，经 `marked` 和 `DOMPurify` 后渲染；提供停止、重新生成、错误和规则回退状态。
5. 数据留痕：推理记录保存完整解释快照；普通用户只返回公共字段，场景管理员和系统管理员可查看算法专属中间值。
6. 后续增强：补齐算法训练阶段质量指标、场景字段字典校验、AI 服务连通性和完整联调。

## 当前实现边界

算法的训练、正式 `distributionForInstance` 预测和风险阈值逻辑未改动。`feature_attribution` 是预测后的单特征屏蔽敏感性诊断，不参与模型训练或最终分类。无法从现有服务获得的专属中间参数不会被推测或伪造。

## 本地配置

AI 设置保存需要 `AUTH_SESSION_PEPPER` 或 `AI_SETTINGS_ENCRYPTION_KEY`，至少 32 个字符。首次保存用户 AI 设置时必须填写 API key；后续修改地址或模型时留空即可保留原 key。数据库迁移使用：

```powershell
cd backend
alembic upgrade head
```

前端设置页只提交用户当前输入的 key；后端按用户 ID 加密保存，查询只返回掩码。AI 服务地址支持标准 OpenAI Chat Completions 兼容地址，例如 `https://api.openai.com/v1` 或内网兼容服务地址，服务端会自动补齐 SDK 所需路径。不要把 `AI_SETTINGS_ENCRYPTION_KEY`、`AUTH_SESSION_PEPPER` 或用户 API key 写入前端环境变量、日志和仓库。

本地 Mock AI 可直接启动：

```powershell
python scripts/mock_openai_server.py --port 8765
```

然后在设置页使用 `http://127.0.0.1:8765/v1` 和任意测试 key；故障回退场景可将 `--mode` 改为 `empty`、`rate_limited`、`authentication_failed` 或 `model_not_found`。

数据库和后端启动后，可以使用联调脚本自动执行“登录 → 选择已发布模型 → 生成合法样本 → 预测 → SSE → 历史解释复用”：

```powershell
python scripts/run_stage9_smoke.py --configure-mock
```

脚本默认使用 `alice / alice123`，也可以通过 `SMOKE_USERNAME`、`SMOKE_PASSWORD`、`SMOKE_API_BASE_URL` 和 `SMOKE_MOCK_AI_URL` 覆盖。未传 `--configure-mock` 时不会写 AI 配置，只使用账号已有配置。

数据库不可用时，模型推理和接口代码仍可通过纯函数检查验证；完整联调需要先启动根目录 `docker compose up -d db`，再执行上面的迁移。当前机器若 Docker Desktop 未运行，迁移不会自动修改数据库。
