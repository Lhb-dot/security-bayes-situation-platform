# 权限模型与鉴权模块（2026-10 定稿）

本文件是**数据鉴权**的说明文档。唯一实现是 `backend/app/security/policy.py` 的
`Authz`；服务层不再各自书写 `if role == ...` 的可见性分支。认证（登录 / 会话 /
CSRF）另见 `backend/app/utils/auth.py` 与 `backend/app/api/deps.py`，本文件不涉及。

## 一、角色

| 角色 | 常量 | 定位 |
| --- | --- | --- |
| 系统管理员 | `SUPER_ADMIN` | 服务提供方：看平台统计 + 自己的数据，看不到各公司具体数据 |
| 场景管理员 | `SCENARIO_ADMIN` | 本场景最高权限；**场景之间严格隔离** |
| 场景用户 | `SCENARIO_USER` | 只看自己 + 平台/公司共享的数据 |

## 二、数据级别（仅数据集携带）

`dataset.visibility` **由上传者角色决定、创建后不可变、调用方不可自选**
（`default_dataset_visibility`）：

| 上传者 | 级别 |
| --- | --- |
| `SUPER_ADMIN` | `platform` |
| `SCENARIO_ADMIN` | `company` |
| `SCENARIO_USER` | `personal` |

## 三、可见性矩阵

| 资源 | SUPER_ADMIN | SCENARIO_ADMIN | SCENARIO_USER |
| --- | --- | --- | --- |
| 数据集 | 仅 `platform` | 本场景全部（含 `personal`） | 本场景 `platform`+`company` + 本人 `personal` |
| 模型 | 仅本人训练 | 本场景（超管未发布的除外） | 本场景已发布/推荐 |
| 推理记录 | 仅本人 | 本场景全部 | 仅本人 |
| 风险事件（明细） | 仅本人 | 本场景全部 | 仅本人 |
| 风险事件（统计） | 平台全量 | 本场景 | 本人 |
| 处置记录 | 跟随事件 | 跟随事件 | 跟随事件 |
| 报告 | 仅本人 | 仅本人 | 仅本人 |
| 态势快照 | 全部（仅统计） | 本场景 | 无 |
| 用户管理 | 仅 `SCENARIO_ADMIN` | 本场景 `SCENARIO_USER` | — |

补充规则：

- 报告**全部相互独立**，任何角色都只看到本人生成的报告。
- 推理记录、数据集：**能看见即可删 / 可管理**（见 `can_manage_*`）。
- 风险事件**只能隐藏，不能删除**；处置记录不提供删除。
- 训练 SUPER / SA 都可做；发布、下线、推荐**本场景任意 SA** 均可，不限定训练人；
  「推荐」不唯一（同一场景+数据集可推荐多个）。
- 阈值、AI 设置、报告等**跟随账号**。

## 四、怎么用（服务层）

```python
# 列表 / 聚合：给 SELECT 追加可见性条件
stmt = self.authz.scope_datasets(stmt, current_user)
stmt = self.authz.scope_events(stmt, current_user)        # 明细口径
stmt = self.authz.scope_event_stats(stmt, current_user)   # 统计口径（SUPER=平台全量）

# 单条读写：判定 + 断言
if not self.authz.can_view_dataset(current_user, dataset):
    raise ServiceError(403, "无权限操作")
self.authz.require_view_model(current_user, model)

# 动作能力
self.authz.can_train(current_user)
self.authz.can_manage_model(current_user, model)
self.authz.can_manage_user(actor, target)
```

`ServiceBase.__init__` 已经注入 `self.authz`，服务无需自己 `new`。

## 五、新增一个受保护资源

1. 在 `Authz` 里加一组方法：`scope_<resource>` / `can_view_<resource>` /
   `require_view_<resource>` / `can_manage_<resource>`；
2. 服务层改调这些方法，删除原来的角色分支；
3. 列表接口用 `scope_*`，单条接口用 `require_view_*`；
4. 补一个 `tests/test_security_boundaries.py` 风格的边界测试。

## 六、前端

前端隐藏导航 / 路由守卫只是体验，不是鉴权。页面级角色准入的唯一来源是
`frontend/src/router/access.ts`（`PAGE_ROLES` / `rolesForPath`），路由 `meta.roles`
与顶部导航共用它；当前用户角色统一读 `useUserStore()` 的 getter
（`isSuperAdmin` / `isScenarioAdmin` / `isManagement`）。
