### 1.2 实现要求

新增内容指纹函数（模块级，带进程缓存）：

```python
_FINGERPRINT_CACHE: dict[int, tuple[float, int, str]] = {}

def content_fingerprint(dataset) -> str:
    """文件内容指纹："{size}-{sha1(全文)[:16]}"；文件缺失返回 "missing:{logical_id}"。"""
```

- 用 `_file_signature(path)`（已存在）做 (mtime, size) 缓存键，命中直接返回。
- 用 `hashlib.sha1()` 分块读（1MB/块），避免大文件一次性入内存。
- 缓存结构必须与 `_HEADER_CACHE` / `_LABEL_STATS_CACHE` 同风格，用 `_CACHE_LOCK`。

改造 `_effective_groups`（`：639-643`）为两遍分组：

```python
CARRIER_GROUP_ID = "carrier_shared_source"

def _effective_groups(datasets):
    # 显式同源族：carrier 三份是同一批 507 条样本的三种编码（内容不同、语义同源）
    carrier_fps = {content_fingerprint(d) for d in datasets if d.logical_id in CARRIER_LOGICAL_IDS}
    groups = defaultdict(list)
    for d in datasets:
        fp = content_fingerprint(d)
        key = CARRIER_GROUP_ID if (d.logical_id in CARRIER_LOGICAL_IDS or fp in carrier_fps) else fp
        groups[key].append(d)
    return groups
```

要点：
- **不能只按指纹分组**——carrier 三份内容 MD5 各不相同（biaoqian `6296CCE2…`、paired_trail `1C95B0A5…`、lisan `77CB74B6…`），必须保留显式族。
- `carrier_track_company_v1` 内容 = lisan → 经 `carrier_fps` 命中并入 `carrier_shared_source` 族，**不得**单独成组。
- `_representative`（`:646-651`）保持「优先 `CARRIER_CANONICAL`，否则 `group[0]`」不变。

**验收（进程内实测，必须全部成立）**：
```

power      dataset_count=1  dataset_file_count=2  sample_count=2000
flightdeck dataset_count=1  dataset_file_count=4  sample_count=507
geological dataset_count=5  dataset_file_count=6  sample_count=16385
```
（以 SCENARIO_ADMIN 视角。**2026-09-27 实施后按真实数据修正了三处**：① power `sample_count` 2013 → **2000**，该 ARFF 恰好 2000 行 `@DATA`，契约自带的参考 `sha256=4CB117BD…` 与该文件逐位一致，是 2013 这个数字错；② geological `dataset_count` 6 → **5**，`geo_slope_company_v1` 与 `dis_landslides` 字节完全相同，按 §1.2 的分组规则必然合并，与 network 的 `net_flow_company_v1 ≡ nf_unsw_nb15_v2` 同构；③ 连带 geological `sample_count` 21570 → **16385**、`risk_count` 7188 → **4594**。

## 3. P1：`describe()` 新增字段（`dashboard_service.py:618-631`）

`DatasetStat` 每项新增（保持已有 8 个字段不变）：

| 字段 | 类型 | 来源 |
|---|---|---|
| `attribute_count` | `int` | `len(self.fields(dataset))` |
| `field_names` | `string[]` | `[f["name"] for f in fields]`（顺序同 ARFF；`read_arff_header` 的字段结构见 `utils/arff_reader.py`） |
| `visibility` | `string` | `dataset.visibility` |
| `uploader_role` | `string \| null` | `dataset.uploader_role` |
| `uploaded_at` | `string \| null` | `dataset.uploaded_at.isoformat()` |
| `source_group` | `string` | 该数据集所属同源组 key（见 §1） |
| `content_fingerprint` | `string` | `content_fingerprint(dataset)` |
| `positive_labels` | `string[]` | `sorted(DATASET_POSITIVE_LABELS.get(logical_id, set()))` |
| `label_values` | `string[]` | 标签列实际取值，按计数降序，**最多 12 个** |
| `label_kind` | `string` | `"binary"` / `"multiclass"` / `"numeric"` / `"unknown"` |
| `caliber_registered` | `bool` | `logical_id in DATASET_RISK_TYPES` |

**`label_kind` 判定规则**（纯描述性，不参与正类判定）：
- 取标签列去重值集合 `V`（忽略空/`?`）。`len(V)==0` → `"unknown"`。
- `len(V)==2` → `"binary"`。
- `len(V)>2` 且全部可 `float()` → `"numeric"`（如 `landslides {0..9,11}`）。
- `len(V)>2` 且不可全转数值 → `"multiclass"`（如 `landslide_size`）。
- 为拿到 `V`：`_DatasetReader` 已有 `tally_arff_column` 快速路径（`:601-616` 的 `_tally_label` 用它）。新增一个带缓存的方法，如
  `label_value_counts(dataset) -> Counter`，复用 `tally_arff_column(path, index, len(fields))`，失败回退 `rows()`。
  **必须复用 `_LABEL_STATS_CACHE` 同风格的进程缓存**，不得每次全量解析。

`describe()` 需要拿到 `source_group`，因此签名可改为 `describe(self, dataset, source_group: str | None = None)`；`get_profile` 里先用 `_effective_groups` 建 `{dataset.id: group_key}` 映射后传入。

## 8. 四场景特色块与特色 KPI

### 8.1 network（`ProfileNetwork.vue`）

- **D1「数据集风险口径可比性矩阵」** `DashCard` + `DashTable`，数据 `caliber_matrix`。
  列：数据集 / 标签字段 / 正类取值（`positive_labels.join('、')`）/ 与场景合并口径偏离（`deviation` → 显示 `×N`，>1 标红、<1 标蓝）/ 登记状态。
  `source` 写「按数据集逐行对比 · 统一正类口径」。
  *（2026-10-09 去重：样本量 / 风险样本 / 风险占比已移除 —— 资产属性归 S2；「未登记」由本表「登记状态」承载，S2 不再重复挂标签。）*
- **D2「流量统计维度覆盖矩阵」** `DashCard` + `DashTable`，数据 `dimension_coverage`。
  列：统计维度 / 覆盖数据集（`datasets` 映射为展示名，逗号分隔）/ 覆盖数（`datasets.length`）/ 状态（`=== dataset_file_count` 为「全覆盖」，`=== 1` 为「仅一份数据支撑」）。
- **特色 KPI**：「风险口径分裂度」= `new Set(caliber_matrix.map(r => r.label_field)).size`，`sub` = 「N 套风险语言 · 不可直接合并」。

### 8.2 power（`ProfilePower.vue`）

- **D1「电参量基线一致性（跨数据集）」** `DashCard` + `DashTable`，数据 `telemetry_by_dataset`。
  列：数据集 / 电压均值 / 电流均值 / 温度均值 / 工频合格率 / 遥测丢包率 / 结论（`baseline_ok ? '达标' : violations.join('、')`，不达标标红）。
  `source` 写「电力基线：电压 300–700 kV · 电流 400–1600 A · 温度 30–90 ℃ · 工频 49.8–50.2 Hz · 丢包 ≤1%」。
  *（2026-10-09 去重：样本量已移除 —— 归 S2。本表不含口径，故 `标签字段` 保留在 S2。）*
- **D2「设备 × 系统 覆盖矩阵」** `DashCard` + `DashTable`，数据 `component_matrix`。
  列：设备/系统 / 类型（`kind`）/ 各数据集样本量（动态列或合并成一列「覆盖数据集：A(1200, 40.0%)、B(…」）/ 覆盖数。
- **特色 KPI**：「工频合格率」= `telemetry_by_dataset` 按 `record_count` 加权平均的 `frequency_pass_rate`，`sub` = 「49.8–50.2 Hz 区间占比」。
- 原 11 张研判卡（协议/端口/包长/电参量/设备排行等）**全部移除**，但后端字段保留。

### 8.3 flight_deck（`ProfileFlightdeck.vue`）

- **D1「同源编码族治理表」** `DashCard` + `DashTable`，数据 `encoding_family`。
  列：数据集 / 同源组 / 编码形态（`numeric`→数值连续、`interval`→离散区间、`paired`→配对轨迹、`unknown`→未知）/ 正类数 / 正类一致性（`collision_consistent` → 一致/不一致）。
  `source` 写「同源组内为同一批样本的不同编码 · 只应保留一份入模」。
  *（2026-10-09 去重：字段数 / 样本量归 S2，已发布模型数归 S3。本表不含口径，故 `标签字段` 保留在 S2。）*
- **D2「同源冗余度与去重收益」** `DashKpis` + `DashCard` + `DashBars`，数据 `redundancy` + `groups`。
  KPI：去重前样本（`raw_samples`）/ 去重后样本（`deduped_samples`）/ 被吸收数据集数（`file_count - effective_group_count`）。
  *（2026-10-09 去重：「同源冗余率」不在此处 —— 它已是 S1 第 4 个 KPI，同一个数同页只出现一次。）*
  `DashBars`：每个 `groups[]` 一根柱 = `file_count`。
- **特色 KPI**：「同源冗余率」= `redundancy.redundancy_rate`，`sub` = `{file_count} 份文件 → {effective_group_count} 个有效数据集`。
- 原 12 张研判卡（间距/方向角/雷达等）**全部移除**，尤其 `双机方向角对比雷达`（与用户首页完全同款）。

### 8.4 geological（`ProfileGeological.vue`）

- **D1「数据集角色分工矩阵」** `DashCard` + `DashTable`，数据 `roles`。
  列：数据集 / 角色 / 标签字段 / 标签类型（`label_kind` 中文化）/ 建模与研判状态。
  「建模与研判状态」是**四态结论** —— 把原先的「参与训练」「产生风险事件」两个二值列压成一列：
  `已入模` / `待建模 · 有风险口径`（该建未建，真告警）/ `设计内不入模`（全球编目表、随机基线集）/ `未登记 · 不产事件`（管理告警）。
  *（2026-10-09 去重：字段数 / 样本量 / 风险占比归 S2 —— 本表只讲职责，不复述资产属性。）*
- **D2「地形因子跨数据集覆盖矩阵」** `DashCard` + `DashTable`，数据 `factor_coverage`。
  列：因子 / 覆盖数据集 / 覆盖数 / 分箱一致性（`consistent_binning` → 一致/不一致；**覆盖数为 1 时显示「单源无从比较」**，不能显示「一致」）。
- **特色 KPI**：「未建模数据集数」= `modeling.filter(m => m.total === 0).length`，`sub` = `{dataset_file_count} 份数据中 N 份无模型`。
  ⚠️ 口径提醒：`modeling` 按**文件**计（6 条），而 KPI 1 的 `dataset_count` 按**内容指纹去重**计（5 个），

- **必须移除**：`近期待处置事件·按风险分排序`（`DashEvents`，执行端清单）、`8 个地形因子均值`、`地质灾害触发因素分布`、`灾害类型分布`、`规模分布与国家 TOP`。
- **保留**：风险事件处置进度漏斗、近 10 天活动趋势、场景成员（这三块已是合格的管理员组件，可沿用现有实现或并入 S4/S5）。
