# 统一解释数据契约 v1

## 目标

统一解释数据只表达服务端已经得到的模型事实和场景配置，不参与训练、预测标签、预测概率或风险阈值计算。契约版本为 `1.0`，保存在 `explain_data.contract_version`。

## 公共字段

| 字段 | 类型 | 缺失规则 | 可见角色 |
| --- | --- | --- | --- |
| `contract_version` | string | 固定为 `1.0` | 三类角色 |
| `prediction` | string | 未返回时为空字符串 | 三类角色 |
| `prediction_is_risk` | boolean | 默认 `false` | 三类角色 |
| `risk_probability` | number/null | 不可计算时 `null` | 三类角色 |
| `risk_threshold` | number/null | 未配置时 `null` | 三类角色 |
| `confidence` | string | 默认 `低` | 三类角色 |
| `top_features` | array | 无数据时 `[]` | 三类角色，普通用户最多 3 项 |
| `conflict` | object | 固定包含 `has_conflict` 和 `description` | 三类角色 |
| `scenario` | object | 固定包含场景公共说明字段 | 三类角色 |
| `recommended_actions` | string[] | 无配置时 `[]` | 三类角色 |

管理员额外获得 `model_quality`、`algorithm_details` 和 `input_snapshot`。普通用户不返回模型质量指标、算法专属中间值、原始输入快照或完整特征贡献。

## 缺失数据

结构化解释模块统一使用：

```json
{"available": false, "reason": "训练结果未提供交叉验证均值"}
```

数值字段使用 `null`，数组使用 `[]`，对象使用固定结构加 `available=false`。不得用空字符串、`0` 或伪造的默认指标表示缺失。

## 算法专属字段约定

`algorithm_details.algorithm_code` 标识当前算法，`algorithm_details.specific` 使用该算法对应的对象形状。第二阶段先冻结形状，第三阶段再填充只读数据：

```json
{
  "A2WNB": {"original_attributes": [], "enhanced_attributes": [], "probability_change": null, "rode": {"available": false, "reason": "..."}},
  "MAWNB": {"original_view": {}, "spode_view": {}, "random_forest_view": {}},
  "EMAWNB": {"dynamic_view_weights": [], "before_fusion": [], "after_fusion": [], "view_conflict": {}},
  "CAVWNB": {"feature_evidence": []},
  "PMWNB": {"submodels": [], "risk_support_count": null, "disagreement": null},
  "DIWNB": {"original_view": {}, "knn_view": {}, "k": null, "neighbor_risk_ratio": null, "neighbor_class_ratios": [], "consistency": null}
}
```

## 角色权限

- `SCENARIO_USER`：风险结论、概率、阈值、置信度、冲突概况、前三个影响字段、场景说明和建议。
- `SCENARIO_ADMIN`：在本场景授权范围内获得完整契约，包括模型质量、算法明细和输入快照。
- `SUPER_ADMIN`：在平台数据授权范围内获得完整契约，包括模型质量、算法明细和输入快照。

所有记录访问仍先经过推理记录的用户、场景和数据集权限检查；契约裁剪不能替代记录级授权。
