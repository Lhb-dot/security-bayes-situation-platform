# 前端更新记录

## 2026-07-30：RiskAnalysis.vue 重构（对齐需求 6.2 P0 业务闭环）

### 修改文件

| 文件 | 操作 | 说明 |
|:-----|:-----|:------|
| `src/services/mockApi.ts` | 新增 | 添加 `TrainResult` 接口和 `trainModel()` 函数（模拟贝叶斯模型训练，返回 Acc/Rec/F1/G-mean） |
| `src/views/RiskAnalysis.vue` | 重写 | 完全重写，对齐全站架构 |

### 旧版问题

- 直接调用 `@/api/modelApi`（后端 API），无 mock 回退，无后端时不可用
- 推理输入写死 3 个字段（feature1/2/3），不符合需求 6.2 "根据数据集固定字段生成输入项"
- 使用 JSScript（非 TypeScript），与全站 `<script setup lang="ts">` 不一致
- UI 使用 Element Plus 默认亮色样式（`#ccc` 边框），与暗色科幻主题冲突
- 数据集用 `dataset_name` 文本匹配，与其他页面统一用 `dataset_id` 不一致

### 新版设计

- **TypeScript**：`<script setup lang="ts">` 全型安全
- **数据层**：全部接入 `@/services/mockApi`，无后端依赖
- **两列布局**：
  - 左侧：**模型训练**（场景选择 → 数据集选择 → 算法/离散方式 → 训练 → 展示 Acc/Rec/F1/G-mean 指标卡片）
  - 右侧：**风险推理**（训练完成后激活 → 根据数据集固定字段动态生成输入项 → 执行推理 → 展示风险等级/概率/原始标签/推荐措施）
- **动态字段**：字段来自所选数据集的 `DatasetField[]`，排除分类标签，按 `field_type` 区分 float/int/string 输入控件
- **暗色主题**：与 `RiskInference.vue` 一致的暗色科幻风格（`rgba` 半透明背景、渐变按钮、发光边框）
- **航母甲板**：场景选项不包含（航母甲板不可用于训练），符合需求 1.1(4)

### 业务流对齐

```
场景选择 → 数据集选择 → 模型训练（PMWNB/朴素贝叶斯/贝叶斯网络）
  → 展示 Accuracy/Recall/F1/G-mean（需求 6.2 Table）
  → 根据固定字段动态生成输入项（需求 6.2 "单条样本推理"）
  → 执行推理 → 输出风险概率和风险等级（需求 5.2）
```

```

## 2026-07-30：修复表格"白内障"颜色问题（暗色主题一致性修正）

### 问题描述

Element Plus 表格背景设为 `transparent` 时，会透出其内部默认的亮色层，导致表格呈"白蒙蒙的跟白内障一样"的视觉效果。涉及 DatasetCenter、AlertsView、ReportCenter 三个页面。

### 修改文件

| 文件 | 操作 | 说明 |
|:-----|:-----|:------|
| `src/views/DatasetCenter.vue` | 修改 | 表格背景从 `transparent` 改为实色深色 rgba，替换 el-tag 为自定义徽章 |
| `src/components/AlertsView.vue` | 修改 | 同 DatasetCenter，表格背景 + el-tag 替换 |
| `src/views/ReportCenter.vue` | 修改 | 同 DatasetCenter，表格背景 + el-tag 替换 |

### 统一修复方案

所有 Element Plus 表格的全局 `<style>` 覆盖改为以下实色值：

| 样式目标 | 旧值 | 新值 |
|:---------|:-----|:------|
| 表格单元格背景 | `transparent` | `rgba(6,15,28,0.85)` |
| 斑马纹背景 | `rgba(255,255,255,0.02)` 或类似半透明 | `rgba(10,24,44,0.85)` |
| 悬停高亮 | `rgba(91,166,255,0.06)` | `rgba(20,44,72,0.9)` |
| 表头背景 | 各种半透明蓝色 | `rgba(16,34,60,0.9)` |
| 表格文字 | `#d9e8ff` 或 `#9ad6ff` | `rgba(175,198,230,0.85)` |
| 容器背景 | `rgba(11,22,40,0.6)` | `rgba(8,18,34,0.7)` |

### 额外替换

- **AlertsView**：风险等级 `el-tag` → 自定义 `.ev-level-badge` 类（`ev-level--HIGH/MEDIUM/LOW`）；处置状态 `el-tag` → 自定义 `.ev-status--待处置/处理中/已处置`
- **DatasetCenter**：格式 `el-tag` → 自定义 `.format-badge--arff/csv/json`；数据类型 `el-tag` → 自定义 `.type-badge--numeric/string`
- **ReportCenter**：格式 `el-tag` → 自定义 `.format-badge--pdf/html/markdown`

### 需求依据

保持全站暗色科幻主题视觉一致性，消除 Element Plus 默认亮色层透出导致的白色雾气感。

### 已验证

```

## 2026-07-30：修复首页（/dashboard）底部异常"重试"框

### 问题描述

首页大屏最底部出现一个突兀的卡片，里面有一个"重试"按钮。经排查，这是 `App.vue` 模板里**错误兜底状态卡片被无条件渲染**导致的，而非布局问题。

### 根因分析

`App.vue` 模板中有两组独立的渲染判断：

1. 主页面 `<main>`（首页/告警列表/告警详情）用独立的 `v-if="!isRiskPage && !loading && !error && dashboard"` 渲染；
2. 从 "AI研判页" 开始的 `v-if` / `v-else-if` 链：
   - `isRiskPage` → 风险研判页
   - `isNewRoutePage` → 多场景新页面
   - `loading` → 加载中
   - **最后一个 `v-else` 无条件兜底**渲染错误卡片

在 `/dashboard` 页数据加载成功后：`isRiskPage`、`isNewRoutePage`、`loading` 三个条件均不成立，于是最后一个 `v-else` **无条件渲染**，把"重试"错误框显示在正常大屏下方。

### 修改文件

| 文件 | 操作 | 说明 |
|:-----|:-----|:------|
| `src/App.vue` | 修改 | 错误兜底卡片从无条件 `v-else` 改为 `v-else-if="error"` |

### 改动内容

```diff
- <section v-else class="state-card state-card--error">
+ <section v-else-if="error" class="state-card state-card--error">
    <p>{{ error }}</p>
    <button class="ghost-button" @click="loadData">重试</button>
  </section>
```

现在错误卡片只在 `error` 变量真正有内容（加载确实失败）时才显示，正常加载成功后不再出现。

### 附带：DashboardView 网格修正（排查过程中一并修复）

排查时曾误判为布局问题，顺带修正了 `DashboardView.vue` 的网格覆盖：

| 样式目标 | 旧值 | 新值 |
|:---------|:-----|:-----|
| `.dashboard-grid` 列数 | `1.6fr 1.4fr`（2 列，覆盖全局 12 列语义） | `repeat(12, minmax(0, 1fr))`（与全局 span 12/8/4 匹配） |
| `.right-chart-group` | 只有 `grid-row: span 3` | 补上 `grid-column: span 4` |
