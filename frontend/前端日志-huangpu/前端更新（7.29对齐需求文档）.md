## 一、改造背景

本次改造基于上一轮完成的 5 个新页面（模型中心、风险研判、态势分析、报告中心、系统设置）和路由/导航体系，进一步将**数据层和现有组件**精确对齐至 `requirements-analysis.md` 需求文档，解决上一轮间隙分析（gap analysis）中发现的重大不匹配项。

### 核心问题

| 问题 | 严重程度 |
|:-----|:---------|
| RiskEvent 类型仅 8 字段 vs 需求 5.2 节要求的 12 字段 | 🔴 P0 |
| 数据集字段缺少 `field_role`（输入特征 vs 分类标签） | 🔴 P0 |
| SCENARIO_META 使用虚构 5~8 字段 vs 需求第 3 节要求的真实 41/9 字段 ARFF | 🔴 P0 |
| 航母甲板（flightdeck）有假数据 vs 需求 3.5 节定义的"暂未接入" | 🔴 P0 |
| 训练页面缺少 G-mean 指标 | 🟡 P0 |
| 推理页面使用固定 5 输入字段 vs 需求要求的动态数据集字段驱动 | 🟡 P0 |
| 告警中心使用旧 AlertRecord vs 统一 RiskEvent | 🟡 P0 |
| 场景卡片状态标签与需求不一致 | 🟢 P1 |

#### `RiskEvent` 接口 — 完全重写

严格匹配需求文档 **5.2 节** 12 字段结构：

```typescript
export interface RiskEvent {
  event_id: string;
  scenario_id: ScenarioId;
  dataset_id: string;            // ★ 新增
  model_version_id: string;      // ★ 新增
  original_label: string;        // ★ 新增
  risk_type: string;
  risk_level: 'HIGH' | 'MEDIUM' | 'LOW';
  risk_score: number;
  occurred_at: string;
  status: '待处置' | '处理中' | '已处置';
  raw_features: Record<string, unknown>;  // ★ 新增
  description: string;
}
```

**关键变更对照：**

| 旧字段 | 问题 | 新字段 |
|:-------|:-----|:-------|
| `title: string` | 需求无此字段 | → 移除，改由 `risk_type` 标识 |
| `event_type: string` | 命名与需求不一致 | → 改用 `risk_type` |
| `source: string` | 需求无此字段 | → 移除 |
| `risk_level: 'critical'\|'high'\|'medium'\|'low'` | 含 critical 四档，小写 | → `'HIGH'\|'MEDIUM'\|'LOW'` 三档大写 |
| `risk_probability: number` | 字段名不匹配 | → `risk_score: number` |
| `timestamp: string` | 字段名不匹配 | → `occurred_at: string` |
| `status: 'active'\|'resolved'` | 英文值不匹配 | → `'待处置'\|'处理中'\|'已处置'`（中文三态） |
| `(无)` | 缺少 4 个必需字段 | → 新增 `dataset_id`、`model_version_id`、`original_label`、`raw_features` |

### 2.2 `src/services/mockApi.ts` — 模拟数据完全重构

#### SCENARIO_META 数据集精确匹配需求第 3 节

| 数据集 | 旧值 | 新值 | 依据 |
|:-------|:-----|:-----|:-----|
| **KDDTrain+ 20 Percent**（网络安全） | 8 个虚构字段（csv） | **41 个 ARFF 字段**（40 输入 + 1 标签 `class`） | 需求表 3.1 |
| **NF-UNSW-NB15-v2**（网络安全） | 7 个虚构字段（csv） | **41 个 ARFF 字段**（40 输入 + 1 标签 `Label`） | 需求表 3.2 |
| **PowerGrid Knowledgebase**（电力系统） | 6 个虚构字段 | **9 个 ARFF 字段**（8 输入 + 1 标签 `Target_Event`） | 需求表 3.3/3.4 |
| **航母甲板保障作业** | 3 个假数据集 | **`datasets: []`** — 无数据集 | 需求 3.5 |
| 旧假数据集（NSL-KDD、CIC-IDS2017、停电风险、舰面调度等） | 存在 | **全部移除** | 需求表严格匹配 |

所有字段名、字段类型、业务含义严格对应需求文档表 3.1~3.4 的 ARFF 定义。字段顺序与文档一致，最后一个字段自动判定为 `'分类标签'`，其余为 `'输入特征'`。

#### 新增/修改函数一览

| 函数 | 变更说明 |
|:-----|:---------|
| `generateScenarioCard()` | 航母甲板 → `status: 'inactive'`，各项计数为 0 |
| `generateScenarioDetail()` | 航母甲板返回空数组；RiskEvent 使用新 12 字段结构 |
| `generateDatasets()` | 航母甲板返回 `[]`；所有字段追加 `field_role`（末字段 = '分类标签'，其余 = '输入特征'） |
| `generateGlobalOverview()` | 只统计 `status === 'active'` 的场景，航母不计入 |
| `generateSituationData()` | 航母甲板返回空数据 |
| `generateReports()` | 排除航母甲板场景 |
| `createAlert()` | 排除航母甲板（只从活跃场景中采样） |
| **`getRiskEvents()`** | **★ 新增** — 聚合所有非航母场景的 RiskEvent，按 `occurred_at` 降序排列 |

#### `InferenceResult` 接口更新

```typescript
export interface InferenceResult {
  risk_level: 'HIGH' | 'MEDIUM' | 'LOW';
  risk_probability: number;
  original_label: string;   // ★ 新增
  risk_type: string;        // ★ 新增
  recommendation: string;
  model_used: string;
}
```

`getInferenceResult()` 输入签名从固定 5 个参数改为 `Record<string, unknown>`，适配动态字段推理场景。
